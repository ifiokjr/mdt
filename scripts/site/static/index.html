The whole language

Four tags.
That's it.

mdt tags are HTML comments, so they vanish when markdown renders. No build step in your docs, no new file format, nothing to learn past this row of cards.

{@name}

Provider

Defines a block once, in a *.t.md template file.

{=name}

Consumer

Marks a spot that should hold a copy. Markdown or code comments.

{~name:""}

Inline

A one-line value, like a version number in the middle of a sentence.

{/name}

Close

Ends any block. Everything between the tags belongs to mdt.

Where it works

Docs that live
in your code.

Consumers work inside source comments, so your doc comments, your README, and your docs site can all quote the same paragraph. A transformer adds the comment marker to every line.

//! <!-- {=clientDocs|trim|linePrefix:"//! ":true} -->
//! A fast HTTP client.
//!
//! Supports async and blocking modes.
//! <!-- {/clientDocs} -->
pub struct Client;
/**
 * <!-- {=clientDocs|trim|linePrefix:" * ":true} -->
 * A fast HTTP client.
 *
 * Supports async and blocking modes.
 * <!-- {/clientDocs} -->
 */
export class Client {}
/// <!-- {=clientDocs|trim|linePrefix:"/// ":true} -->
/// A fast HTTP client.
///
/// Supports async and blocking modes.
/// <!-- {/clientDocs} -->
class Client {}
class Client:
    """
    <!-- {=clientDocs|trim|indent:"    "} -->
    A fast HTTP client.

    Supports async and blocking modes.
    <!-- {/clientDocs} -->
    """
// <!-- {=clientDocs|trim|linePrefix:"// ":true} -->
// A fast HTTP client.
//
// Supports async and blocking modes.
// <!-- {/clientDocs} -->
type Client struct{}

Small, sharp tools

More than
copy and paste.

Pull values from your manifests, reshape a block for each place it lands, and fail the build the moment two copies disagree.

Data in, docs out

Point mdt at package.json, Cargo.toml, or any data file. The version in your docs is the version you ship.

# mdt.toml
[data]
pkg = "package.json"

<!-- {@install} -->
npm i my-lib@{{ pkg.version }}
<!-- {/install} -->

Transformers

One block, many shapes. Trim it, fence it, indent it, prefix every line, or replace text on the way out.

<!-- {=install|trim
  |codeBlock:"sh"} -->
```sh
npm i my-lib@0.9.7
```
<!-- {/install} -->

Drift fails CI

mdt check exits non-zero when any copy is stale and tells you exactly which block, in which file. Add one line to your workflow.

# .github/workflows/ci.yml
- run: npx -y @m-d-t/cli check

Check failed.
  block `install` at readme.md:3:1
Run `mdt update`.

Built for agents

Your agent writes it once.
mdt puts it everywhere.

Agents are great at editing docs and terrible at remembering the four other places the same sentence lives. mdt gives them one place to write and a command that proves nothing drifted.

  • An agent skill built into the binary: mdt skill --install .claude/skills
  • An MCP server with tools to list, preview, check, and update blocks
  • A language server for go-to-provider, hovers, and diagnostics in your editor
$ mdt check
Check failed.
  stale consumers: 2

Stale consumers:

  block `install` at src/lib.rs:1:5

$ mdt check
